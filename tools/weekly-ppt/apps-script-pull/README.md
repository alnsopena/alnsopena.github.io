# Entrega corporativa de borradores PPT por consulta programada

Este proyecto de Apps Script funciona **sin web app ni acceso anónimo**. La PPT se genera los lunes a las 09:00 de Lima o a pedido. Un activador de la cuenta corporativa **solo consulta** cada 15 minutos si hay un borrador cifrado nuevo en GitHub Pages; cuando lo hay, lo autentica, descifra y crea un PPTX editable en [`Estatus semanal/Borradores automáticos`](https://drive.google.com/drive/folders/1GP2-M5Uc_BQCy4YsST0joWoqRhwFjoVD). La carpeta de finales no se modifica. La tarea local de Windows y su artefacto CMS siguen disponibles como respaldo.

**Estado verificado el 30 de septiembre de 2026:** la cuenta de Alonso instaló el activador, un borrador generado a las 12:50 se entregó en Drive a las 12:51 sin pasar por la tarea local, su SHA-256 coincidió con el manifiesto y los reintentos dejaron un solo archivo. La ejecución automática de las 13:04 también terminó correctamente. El portal ya anuncia `delivery:"cloud"`.

## Configuración pendiente, una sola vez

1. Bajo una cuenta de Google Workspace de Andino/COSMOS con permiso de crear archivos en esa carpeta, cree un proyecto **independiente** en [Apps Script](https://script.google.com/) o reemplace el receptor anónimo no desplegado. Copie `Code.gs` y `TweetNaCl.gs` como archivos de script del mismo nombre. Muestre el manifiesto `appsscript.json` y reemplace su contenido con este archivo. Habilite **Advanced Google Services → Drive API v3** si el editor lo solicita. No despliegue una web app.
2. Genere **32 bytes aleatorios** mediante un generador criptográfico y codifíquelos en base64 canónico (44 caracteres, con `=` final). Guarde **el mismo valor** en la propiedad de Apps Script `PPT_PULL_KEY_B64` y en el secreto de repositorio de GitHub Actions `PPT_PULL_KEY_B64`. Esta es la única credencial nueva para el puente. No la incluya en Pages, variables públicas, código, URLs, capturas ni registros. Solo administradores de confianza deben poder editar el proyecto Apps Script, pues sus editores pueden acceder a Script Properties.
3. En el editor, ejecute `installPullTrigger()` **una vez** con esa cuenta y autorice Drive, solicitudes HTTP externas y gestión del activador. Crea un activador único de 15 minutos para `pullLatestWeeklyPpt()`. La cuenta creadora del activador es la identidad que escribe en Drive; cambiar de propietario requiere instalar un nuevo activador con esa cuenta y quitar el anterior. Apps Script puede desplazar ligeramente la hora exacta de ejecución.
4. Lance **Actions → Publicar Portafolio Ejecutivo IT → Run workflow** con `generate_ppt=true`, o use el despachador PMO cuando esté configurado. Espere la publicación de Pages y ejecute manualmente `pullLatestWeeklyPpt()` para la primera prueba. Verifique en las ejecuciones de Apps Script el resultado `{ok:true}`, abra el PPTX en `Borradores automáticos`, y confirme que un segundo usuario corporativo autorizado puede verlo. Ejecute de nuevo: debe devolver `duplicate:true` y conservar un solo archivo. Esta prueba real no se ha efectuado desde el repositorio.
5. Solo después de esa prueba, establezca la **variable** de repositorio `COSMOS_PPT_PULL_VERIFIED=true` y publique de nuevo para que el portal anuncie el puente. Sin esta confirmación, `assets/ppt-config.json` sigue en `delivery:"local"`, aun cuando exista la clave. La variable `COSMOS_PPT_DISPATCH_URL` puede configurarse por separado para el botón de solicitud; aceptar la solicitud no confirma la entrega.

## Cómo funciona y qué revisar si falla

Actions crea `latest.json` y un `.pptx.sb` bajo `portafolio-ejecutivo-it/assets/weekly-ppt-pull/`, y confirma **solo esos archivos cifrados** en Git. El próximo despliegue de Pages los copia; las publicaciones horarias sin PPT conservan ese último asset desde el repositorio. El PPTX sin cifrar permanece únicamente en el espacio temporal de Actions y, tras el pull, en Drive. El `.cms` cifrado existente continúa guardado en el artefacto de Actions para la sincronización local.

El cifrado usa [TweetNaCl.js `secretbox` (XSalsa20-Poly1305)](https://github.com/dchest/tweetnacl-js#secret-key-authenticated-encryption-secretbox), una clave aleatoria de 32 bytes y un nonce aleatorio de 24 bytes para cada borrador. `TweetNaCl.gs` procede de TweetNaCl.js 1.0.3, de dominio público; se adaptó únicamente su destino global a `globalThis`. El cuerpo autenticado incluye nombre, ID e intento de Actions, tamaño, fecha y SHA-256. El receptor compara esos metadatos con el manifiesto público, comprueba el SHA-256 del PPTX después de descifrarlo y solo escribe en el ID fijo de `Borradores automáticos`. `LockService` y `pmoRunKey` evitan duplicados por reintentos. El receptor guarda el identificador de ejecución y el SHA-256 en `appProperties` y también en `properties`, que puede leer el despachador PMO para confirmar la entrega desde otro proyecto. Un mismo nombre con bytes distintos produce `PULL_NAME_CONFLICT` para revisión humana.

Un error en `pullLatestWeeklyPpt()` aparece en **Apps Script → Executions** y puede generar el [correo de fallo de activadores](https://developers.google.com/apps-script/guides/triggers/installable#errors_in_triggers). `PULL_HTTP_404` suele indicar que el primer asset aún no se publicó; `PULL_AUTHENTICATION_FAILED` apunta a claves distintas o rotación incompleta; `PULL_STORAGE_VERIFICATION_FAILED` indica un problema de Drive. Consulte también las [cuotas de Apps Script](https://developers.google.com/apps-script/guides/services/quotas): una descarga permite hasta 50 MB de respuesta, y el código limita la PPT a 10 MB. Para rotar la clave, actualice ambos almacenes de secretos y genere un borrador nuevo; los assets anteriores permanecen cifrados con la clave previa en la historia de Git.

Validación local sin credenciales: `node --test scripts/publish-weekly-ppt-pull.test.mjs scripts/write-ppt-config.test.mjs`. No sustituye la prueba de Workspace, permisos de la unidad compartida y tiempo real de ejecución.
