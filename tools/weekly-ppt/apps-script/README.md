# Receptor POST legado — no desplegar

El Workspace corporativo solo ofrece **Solo yo** o **Cualquier usuario de Andino** para el acceso a web apps. GitHub Actions no tiene sesión Google y no puede llamar este receptor, que requería **Anyone / ANYONE_ANONYMOUS**. El workflow dejó de usarlo. Use el nuevo [proyecto de consulta programada](../apps-script-pull/README.md), que se ejecuta dentro de la cuenta corporativa y descarga el asset cifrado de Pages. La información que sigue describe el diseño antiguo y queda solo como referencia histórica; no configure `PPT_DELIVERY_WEBAPP_URL` ni `PPT_DELIVERY_HMAC_SECRET` para activarlo.

## Diseño archivado

Este código está **listo para desplegar**, pero no está desplegado. La cuenta Google que publique el web app debe poder crear archivos en la unidad compartida de COSMOS. El receptor solo escribe en [`Estatus semanal/Borradores automáticos`](https://drive.google.com/drive/folders/1GP2-M5Uc_BQCy4YsST0joWoqRhwFjoVD); las PPT revisadas por PMO permanecen en la [carpeta original `Estatus semanal`](https://drive.google.com/drive/folders/12eFLOouq6IvpvJ37wkNXYX0BHQilHyiD).

## Configuración, una sola vez

1. Con una cuenta de COSMOS que tenga permiso para **crear archivos** en `Borradores automáticos`, cree un proyecto independiente en [Apps Script](https://script.google.com/) y copie `Code.gs` y `appsscript.json`. Habilite **Advanced Google Services → Drive API v3** si el editor lo solicita. El manifiesto incluido usa el alcance `https://www.googleapis.com/auth/drive` y declara Drive API v3.
2. Cree un secreto aleatorio de al menos 32 caracteres y consérvelo fuera del repositorio. Añada exactamente el mismo valor a **Project Settings → Script Properties → `PPT_DELIVERY_HMAC_SECRET`** y a **GitHub → Settings → Secrets and variables → Actions → Repository secrets → `PPT_DELIVERY_HMAC_SECRET`**. No lo coloque en Variables públicas, Pages, código, logs o URLs.
3. Despliegue como **Web app** con **Execute as: Me / USER_DEPLOYING** y **Who has access: Anyone / ANYONE_ANONYMOUS**. Es necesario porque GitHub Actions llama sin una sesión Google interactiva. Copie la URL HTTPS que termina en `/exec` a otro secreto de Actions llamado `PPT_DELIVERY_WEBAPP_URL`. Esta URL tampoco se publica en Pages. Mantenga el proyecto Apps Script editable solo por administradores PMO de confianza: los editores podrían leer sus propiedades y modificar el código.
4. Ejecute **Actions → Publicar Portafolio Ejecutivo IT → Run workflow** con `generate_ppt=true`. Compruebe que la entrega cloud aparece como exitosa, que el archivo está en `Borradores automáticos` y que abre como PPTX editable. Verifique además que lo ve un segundo usuario autorizado sin usar la PC de Alonso. Si falla, revise la ejecución de Apps Script y la política del dominio; el artefacto `.pptx.cms` queda como respaldo.

El portal puede mostrar un botón de creación directa si se dispone de **otra** web app de despacho protegida para PMO; guarde su URL HTTPS `/exec` en la variable de repositorio `COSMOS_PPT_DISPATCH_URL`. Este receptor anónimo **no** es un botón de despacho y su URL no debe usarse en esa variable. Si no existe esa web app, el portal debe enviar a PMO a GitHub Actions, que requiere inicio de sesión y permiso de escritura en el repositorio. GitHub Pages, al ser estático, no debe contener un token capaz de iniciar Actions.

## Contrato y seguridad

El workflow envía un JSON con el PPTX en base64, fecha en milisegundos, ID e intento de ejecución de GitHub, nonce, nombre, tamaño y SHA-256. Firma los metadatos canónicos con HMAC-SHA256; el receptor recalcula tanto la firma como el hash del archivo. Acepta fechas con menos de cinco minutos de desfase y PPTX de 1 KB a 10 MB. Utiliza `LockService` y la propiedad `pmoRunKey` de Drive para devolver el mismo archivo ante un reintento de la misma ejecución. También evita duplicar por nombre y MD5 un borrador idéntico que la tarea de Windows haya copiado primero. Si ya existe ese nombre con contenido distinto, devuelve `NAME_CONFLICT` para que PMO lo revise. La carpeta de destino está fijada en `Code.gs`; el cliente no puede escoger otra ni escribir en la carpeta de finales. La ejecución de GitHub solo se declara entregada cuando el receptor confirma ID, nombre, tamaño y hash. No se sube ninguna PPT sin cifrar al repositorio o a los artefactos públicos.

El endpoint permite peticiones anónimas, pero **no** permite subidas sin la firma HMAC válida. Si la política de COSMOS impide desplegarlo con acceso anónimo, este puente no puede operar desde GitHub Actions sin una autenticación alternativa aprobada por la organización; no se debe rebajar la validación. La clave HMAC debe rotarse si un editor o administrador de GitHub deja el equipo.

Google documenta `e.postData.contents` como texto, por eso se usa base64. No publica un límite claro para el tamaño de los POST **entrantes** de un web app; la prueba con el PPT real es obligatoria antes de abandonar la tarea de Windows. Apps Script también tiene cuotas y límite de ejecución. Consulte la [documentación de web apps](https://developers.google.com/apps-script/guides/web), [Drive API para unidades compartidas](https://developers.google.com/workspace/drive/api/guides/enable-shareddrives), [permisos de unidades compartidas](https://support.google.com/a/users/answer/12380484?hl=en) y [cuotas de Apps Script](https://developers.google.com/apps-script/guides/services/quotas).
