# Despacho PMO de la PPT semanal

Esta web app privada de Google Apps Script permite que PMO pulse **Generar nuevo borrador** sin abrir GitHub ni encender el PC de Alonso. El servidor llama a `workflow_dispatch` con `generate_ppt=true` y un `request_id` único; el workflow usa ese ID en el título del run. La página consulta ese run y la carpeta **Borradores automáticos** periódicamente. Solo muestra **Abrir borrador** cuando encuentra el PPTX de esa ejecución en Drive. El código no lee monday ni entrega archivos: usa el generador y el puente de entrega del repositorio.

## Publicación

1. Crear un proyecto **independiente** en [Apps Script](https://script.google.com/), bajo una cuenta de Google Workspace de COSMOS. El proyecto debe permanecer bajo control de PMO; no conceder permisos de **editor** del script a usuarios de la web.
2. Copiar `Code.gs` y `Index.html` en archivos del mismo nombre dentro del editor. Activar «Mostrar archivo de manifiesto `appsscript.json`» en Configuración y reemplazarlo con el archivo de esta carpeta. Habilitar **Advanced Google Services → Drive API v3** si el editor lo solicita. El manifiesto incluye permiso de lectura de Drive para comprobar la entrega.
3. Crear en GitHub un **fine-grained personal access token** limitado al repositorio `alnsopena/alnsopena.github.io`, con solo permiso de repositorio **Actions: Read and write** y una caducidad definida. El propietario deberá renovarlo antes de que expire. No añadir permiso Contents: write ni guardar el token en el repositorio, el HTML o el portal. El servidor usa el mismo token para consultar el run; PMO no necesita cuenta de GitHub.
4. En Configuración del proyecto → Propiedades de secuencia de comandos, poner `GITHUB_DISPATCH_TOKEN` al valor del token y `PMO_ALLOWED_EMAILS` a una lista explícita de correos de PMO separados por comas, por ejemplo `persona1@cosmos.com.pe,persona2@cosmos.com.pe`. No añadir correos genéricos ni patrones comodín. El dominio permitido en `Code.gs` es `cosmos.com.pe`; ajustarlo únicamente si la identidad real de Google Workspace usa otro dominio corporativo.
5. **Implementar → Nueva implementación → Aplicación web**: «Ejecutar como yo» (cuenta propietaria con acceso de lectura a **Borradores automáticos**) y acceso «Cualquier usuario de COSMOS» / «Usuarios del dominio». Autorizar los permisos de identidad de correo, solicitud externa y lectura de Drive. Copiar la URL pública del despliegue que termina en `/exec`. Si Google no ofrece el acceso de dominio por política de Workspace, no abrirla a «Cualquiera» como atajo.
6. Abrir la URL con una cuenta PMO incluida en `PMO_ALLOWED_EMAILS` y probar el botón. Confirmar que la página pasa de solicitud aceptada a generación, espera de entrega y finalmente muestra el enlace directo al PPTX correcto en Drive. Recargar la página durante la espera para comprobar que recupera la solicitud. Probar también con una cuenta COSMOS fuera de la lista: debe ver acceso restringido y no generar un run. Si el dominio no entrega el correo activo a Apps Script, el código **deniega** la ejecución; se requiere revisar con administración de Workspace o desplegar como «usuario que accede», en cuyo caso cada PMO debe autorizar la app.

El portal puede seguir mostrando el enlace actual a GitHub Actions hasta completar estas pruebas. Luego se configura la **URL pública no secreta** de la web app en la variable de repositorio `COSMOS_PPT_DISPATCH_URL`, que alimenta `assets/ppt-config.json`; el botón de PMO abrirá esa URL sin editar `index.html`. Solo aceptar URL HTTPS de `script.google.com/macros/s/.../exec`. El PAT **nunca** va en esa variable ni en el archivo público.

## Operación y límites

- El usuario necesita sesión corporativa de Google y debe estar en la lista PMO. Una persona con acceso al portal pero sin autorización PMO no puede lanzar el workflow.
- El servidor vuelve a comprobar identidad y allowlist en cada solicitud, aunque la página ya esté abierta. Conserva la solicitud activa para que cualquier PMO autorizado vea su avance después de recargar. Un segundo clic devuelve esa solicitud mientras no tenga archivo en Drive, fallo terminal o 90 minutos de demora. Además, hay un intervalo mínimo de 90 segundos y no se despacha si ya hay una publicación del workflow en cola o ejecutándose.
- La respuesta de despacho puede traer un ID de run (HTTP 200) o no traerlo (HTTP 204). En ambos casos el servidor verifica el título exacto `PMO PPT <request_id>` antes de confiar en el run. Un run exitoso y el `latest.json` publicado **no** acreditan la entrega: ese manifest puede retrasarse o ser reemplazado por otro. La confirmación exige un PPTX en la carpeta con `properties.pmoRunKey=<run_id>-<run_attempt>` y metadatos válidos. El receptor de Drive debe guardar estas propiedades visibles entre aplicaciones; `appProperties` por sí solas no son visibles para este proyecto independiente.
- La página consulta cada 15 segundos. Si el run falla, muestra el fallo sin enlace. Pasados 90 minutos sin archivo, detiene la consulta automática y ofrece **Comprobar estado ahora**; una entrega tardía puede aparecer al comprobar de nuevo. Los errores temporales de consulta se reintentan hasta cinco veces. Si otro usuario inicia un run manual justo después del control previo, aún puede haber solapamiento porque el puente de Drive publica solo el último manifest; coordinar las generaciones manuales mientras una solicitud PMO esté activa.
- El script conserva como máximo 100 solicitudes durante 30 días y limpia las antiguas al aceptar una nueva. Una solicitud de más de 24 horas ya no se restaura automáticamente al abrir la página.
- El botón ofrece enlaces a [Borradores automáticos](https://drive.google.com/drive/folders/1GP2-M5Uc_BQCy4YsST0joWoqRhwFjoVD) y a [Estatus semanal / finales](https://drive.google.com/drive/folders/12eFLOouq6IvpvJ37wkNXYX0BHQilHyiD). Los permisos de esas carpetas siguen siendo los de Drive.
- Apps Script y GitHub Actions operan sin Codex ni consumo de tokens de Codex. Pueden aplicarse cuotas y límites propios de Google o GitHub. Una solicitud aceptada puede fallar después por monday, generación, cifrado o entrega; el administrador puede revisar el run y la ejecución del activador de Drive para diagnosticarlo.
- Revocar de inmediato el PAT en GitHub si se sospecha exposición. Aunque Script Properties no se publican al navegador, quienes tengan permiso de **editor** sobre el proyecto Apps Script pueden leer/modificar el código y acceder a la credencial.

Validación local sin credenciales: `node --test tools/weekly-ppt/apps-script-dispatch/test-dispatch.mjs`. No hay prueba real de Workspace/Apps Script hasta que se despliegue bajo el dominio y se configure el token.
